# 사고방식
1. 하나의 프로그램 즉 블록이 무엇을 담당하는지?
-> 결국 출력하나를 위해서는 각행에서 제곱평균을 구하고 

1. 출력값 하나의 수식을 쓴다. -> out[0, 2] = h[0, 2] / sqrt((h[0,0]² + h[0,1]² + h[0,2]² + h[0,3]²) / 4 + eps) * w[2]

2. 그 수식이 읽는 입력 범위를 표시한다. (같은 칸? 같은 행 전체? 행렬의 한 행 전체?)
3. 같은 중간값(합, 최댓값, 평균)을 공유하는 출력 칸끼리는 같은 프로그램에 묶는다. 같이 묶어야 그 **중간값**을 한 번만 계산하고 레지스터 안에서 나눠 쓸 수 있어요.
4. 공유하는 게 없는 출력끼리는 다른 프로그램으로 나눈다.
5. 그 조각이 레지스터에 들어가는지, 프로그램 수가 충분한지 확인한다.
--> 결론적으로 프로그램 하나를 기준으로 어딜 잡아야 할지가 보이게됨.


이후에는 필요 도구들을 생각
1. tl.program_id(0) -> 나는 몇번째 행인가? -> 내가 맡을 프로그램별 번호
2. x_ptr + row*stride -> 내 행의 메모리 시작은 어디지?
3. cols = tl.arange(0,BLOCK), mask = cols < N
4. 내 행을 읽기 x, residual
5. 내 행안에서 계산 h, rms, rsqrt, weight
6. 행의 결과를 쓰기 out, h




# 모든 의문점들
tl.load를 통해서 가져오는이유? 왜 load를 하나? 
계산은 레지스터에 있는 값으로만 할 수 있기 때문에
- 텐서 데이터는 gpu의 dram에 존재
- 실제 계산을 하는 연산 유닛은 레지스터에 있는 값만 다룰수 있음
- 따라서 계산할때에는 DRAM 에서 레지스터로 가져와야됨. 그리고 계산후에
결과를 다시 DRAM 으로 내보낼때 tl.store 사용  


# rmsnorm에서 커널 실수한 부분들
1. load 와 store 에 저장하고 읽을떄  텐서시작주소만 넣음 -> 텐서시작주소 + 내 행의 offset까지 넣어야됨.
h_ptr: h텐서의 첫 칸 주소 하나 [1]
h_ptr + row*stride + cols: 내 행의 칸들 주소 묶음 [2048]
h: 레지스터 에 있는 값 ex [2048]


2. x load할때 x_ptr 에서 offset 더하면 됨 (row + offset을 ㅗ실수했었음)

3. weight load할때 (w_ptr + offset 실수했었는데) weigth 텐서는 모든 행이 같은 [N] 벡터이기 떄문에 그냥 w_ptr + cols함녀됨.
